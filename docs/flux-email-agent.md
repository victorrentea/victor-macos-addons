# Flux Email Agent (AgentMail inbox → Terminal claude)

The 📬 poller, its menu item, and the agent launcher — including the security posture that makes the prompt-injection sink acceptable. Do not loosen the sender gates.

- **📬 Flux inbox poller (`FluxInboxPoller` + `FluxMailPolicy`)** — polls the `victor.flux@agentmail.to` AgentMail inbox over its REST API (`AGENTMAIL_API_KEY` from `~/.training-assistants-secrets.env`) **every 10 minutes, and only while the Mac is on AC power** — a tick that lands on battery is skipped entirely, recorded as `skipped — on battery`. Plugged in is when the Mac is at a desk with the power and the network to actually run an agent; on battery it may be in a bag, on a stage, or minutes from empty. It also **polls once ~10 s after launch** rather than waiting a full interval: this app is restarted several times a day, and every restart used to push the next look 10 more minutes out, so mail could sit unclaimed indefinitely. **Two "back at the desk" events poll on the spot** instead of waiting out the tick — the Mac being **plugged into AC** (`PowerMonitor.onSwitchToAC`) and **waking while on AC** (`NSWorkspace.didWakeNotification`) — because that moment is exactly when mail is most likely to be waiting, and nine more minutes of silence is the difference between an agent that answers now and one that answers later. Coming home is *one* arrival that fires those two events in either order (plug in then open the lid, or open the lid then plug in), so they are coalesced into a single poll by the pure `FluxMailPolicy.shouldPollOnArrival` (AC-gated + a 120 s window, which also swallows the notification bursts macOS emits around wake), and the poll is deferred `arrivalSettleDelay` = 8 s because on wake the Wi-Fi has not reassociated yet and an immediate fetch would only log a network error. New mail raises a bottom-left `StatusBanner` and a log line. **Security posture — the inbox is a public address, so every string it yields is hostile input**, and the component is deliberately a *notifier, never an actor*: it runs no shell, launches no agent, and passes nothing to an LLM or interpreter, so there is no prompt-injection sink. **Bodies are never fetched** (metadata only), subjects are truncated to 60 chars before display, and the JSON snapshot is built with `JSONSerialization` (not interpolation) so a crafted subject cannot forge JSON. Two independent sender gates, both of which must pass (`FluxMailPolicy`, 27 unit tests): **(1) exact address match** — the address is parsed from the *last* angle-bracket group of `From:` (defeating the `victorrentea@gmail.com <attacker@evil.com>` display-name spoof) and compared for **equality**, case-insensitively, against `victorrentea@gmail.com`; substring matching is explicitly not used, so `victorrentea@gmail.com.evil.com`, `notvictorrentea@gmail.com` and `victorrentea+x@gmail.com` are all rejected; **(2) verified authentication** — the receiving MTA's `Authentication-Results` stamp must show `dkim=pass header.i=@gmail.com` **and** `dmarc=pass header.from=gmail.com`, failing closed when the header is absent (a bare `From:` is trivially forgeable in SMTP). Gate 2 is defence-in-depth, not proof: a flattened header map can't distinguish the MTA's own stamp from one the sender pasted in — the load-bearing protection remains that nothing downstream acts on content. A **persisted watermark** (UserDefaults, seeded to *now* on first run) plus a bounded seen-id ring mean launching the app never replays the inbox's history, while mail that arrived while the app was down is still caught. **Extending this to hand an email to Claude would reintroduce prompt injection in full and is a separate, deliberately human-approved decision.** Test hook: `GET /test/email`. **The power gate has one manual override: the 📬 menu item (below).** A skipped tick writes no log line, so an unplugged Mac that quietly ignores mail looks identical to one where nothing arrived — that is what the menu item's age suffix is for. `lastCheckedAt` is stamped **only by a poll that actually reached the inbox**, never by a skipped tick, so the menu item cannot claim a freshness it doesn't have. The diagnostics (`lastPollAt`/`lastOutcome`/`lastMatchCount`/`lastError`) are read from three different threads (HTTP server, main, URLSession) and are therefore `NSLock`-protected via `setStatus`/`readStatus`, and the `fetch`/`claim` completions hop back onto the poller's serial `queue` before mutating the watermark and `seen` (they used to mutate them from the URLSession delegate queue despite the comments claiming otherwise).
- **📬 Check task inbox (menu item)** — title carries its own state: `📬 Check task inbox (1m ago, 2🚀)` = the inbox was really read 1 minute ago and 2 Terminal agents have been launched from mail so far. Clicking **forces a poll now, bypassing the power gate** — on battery it is the *only* way an email becomes a task. The age suffix is omitted until the first real poll and the 🚀 count until the first launch (a `0🚀` says nothing an absent one doesn't). The count is `FluxAgentLauncher.launchedCount`, **persisted in UserDefaults** (`flux.agent.launched.count`) and incremented right after `p.run()` succeeds — this app restarts several times a day, and a counter that reset each time would answer "did any mail turn into work?" with a permanent "no". Title formatting is the pure, unit-tested `FluxInboxMenu.title(lastCheck:now:launches:)`; the item re-renders on `menuNeedsUpdate` and on the 1 s tick while the menu is open, so a click's `(checking…)` resolves in place. `GET /test/email` also reports `launched_tasks`.
- **📬→🤖 Flux email agent (`FluxAgentLauncher` + `flux-agent.sh`)** — when the poller admits a new mail/reply from Victor, the Mac opens a **foreground Terminal** running an unattended `claude -p` over the whole email thread, and **mails claude's final message back as a reply in that thread**. The window opens on an **external screen, never the built-in Retina** (`TerminalWindowPlacement`): mail lands mid-workshop and the Retina is what a venue projector mirrors, so an agent window there would show up on the wall in front of the room. It is sized to **10% of that monitor's surface** — an *area* fraction, so each side scales by √0.10 ≈ 0.32 — centred, and falls back to macOS's default placement only when the Retina is the only screen (mirrored displays are skipped: a projector mirroring the Retina is not a second desk). The maths is pure + unit-tested because the two coordinate systems disagree: AppleScript `bounds` count y **down from the top** of the primary screen, `NSScreen` counts it **up from the bottom**. The window's first output is **the mail being answered** (From / Date / Subject + body, `.text` preferred over `.extracted_text`, capped at 4000 chars *for display only* — claude still gets the whole thread), so a glance says which task it is. The heartbeat line reads the way it is scanned — **when, how long, how much**: `[10:49:51] 2m15s — $0.42`. The clock leads so the lines form a column down the window, the elapsed time is `MmSSs` (just `15s` below a minute — a leading `0m` is noise), and the **running spend** comes last, with a `💰 total` when the run ends. `claude` reports `total_cost_usd` only in its *final* result, so a live figure has to be computed from outside: the script pins `--session-id`, finds the transcript claude appends as it works, and prices the token usage (list $/MTok per model family, cache writes 1.25× input and reads 0.1×). Two traps, both handled: the **same usage block is repeated on every entry of one API request** (text, thinking, each tool_use), so summing entries multiplies the bill several times over — dedupe by `requestId`; and the file is being appended to while we read it, so the last line is often half-written — parse per line with `fromjson?` rather than slurping, which would abort on it. The number is an estimate at list price; the run itself is on the subscription. The window **closes itself on any verdict** once the agent is done (unattended runs must not pile up windows); a failed run lingers ~25 s first, and everything is tee'd to a per-day `addons-output/flux-agent-YYYY-MM-DD.log`, so closing never loses a post-mortem. Completion is signalled by a **sentinel file written explicitly at the end of the work, not from the EXIT trap** — `claude` leaves MCP-server children that inherit the script's stdout, so the `>(tee)` process substitution never sees EOF and bash can sit unexited long after the reply is sent; the old trap-based signal therefore fired too late and the window stayed open forever (2026-07-28). **Never two agents for one email** — three layers: (1) the AgentMail **`unread` label is the claim token**, cleared via `PATCH {"remove_labels":["unread"]}` *before* launching and **failing closed** (a missed notification is recoverable, two agents answering the same mail is not) — this is the only layer that survives a wiped watermark or a reinstalled app, since the state is server-side, and `FluxMailPolicy` correspondingly only admits `unread` mail; (2) an in-process `inFlight` set of message ids in `FluxAgentLauncher`; (3) an atomic `mkdir` lock keyed by message id inside the script, reclaimed after 2 h if stale. **Security** — this is the prompt-injection sink I refused to build blind: it is acceptable *only* because `FluxMailPolicy`'s two sender gates (exact address + dkim/dmarc pass) stand in front of it, so **do not loosen them**. Two controls live in the script regardless: the **script sends the reply, never claude**, to the hardcoded `TRUSTED_SENDER` and never to an address parsed out of the email (an injected "forward this to …" cannot exfiltrate by mail, because claude is never handed the send capability); and email text is written to a file and passed **by path**, never interpolated into a shell command line. Message ids are Message-IDs (`<…@mail.gmail.com>`) and **must be percent-encoded** into the API path — unencoded, both the reply and the label PATCH answer a bare `400`. The prompt prefers the **full `.text`** body over `.extracted_text` (extraction strips quoted history and on a short mail can strip everything but the signature, losing the actual request) and is capped at 200 KB (it is passed as one argv entry, so ARG_MAX applies). Claude runs in `FLUX_AGENT_CWD` (default `~/workspace`) on Victor's **subscription** (`env -u ANTHROPIC_API_KEY`), with MCP connectors left **on** — unlike the break-delta, this agent may need to really work in the repos.
