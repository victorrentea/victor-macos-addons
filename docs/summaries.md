# Training-Summary Runs (break delta + wrap-up offer)

- **☕️→📝 Break-summary delta (`BreakSummaryLauncher` + `summarize-on-break.sh`)** — a break >= 5 min ("a section just ended, slack now") opens a Terminal running an unattended `claude` that advances the training-summary **delta**: it reads only the transcript past the `Discussion.md` watermark and appends the new section(s) to **Discussion.md only** (never `ai-summary.md`), so the wrap-up run is a tiny delta + cheap distill instead of one whole-day read. Runs on Victor's Claude **subscription** (`env -u ANTHROPIC_API_KEY`, not the depleted API key) with an empty `--strict-mcp-config` (no connectors = lean startup). A 90s launcher cooldown + a `/tmp/training-summarizer-break.lock` single-instance guard prevent double-runs (a break re-click just resets the timer). **Window lifetime is sentinel-driven, NOT Terminal's `busy` flag:** for a `do script` tab `busy` reads false during startup, so the old `repeat while busy … close` loop closed the window ~1s in and **SIGHUP-killed claude before it wrote anything** (the 2026-06-30 "terminal immediately exited" bug). Now the script writes a unique sentinel file (`ok`/`fail`) when it truly finishes and the launcher waits on that — **auto-closing only on `ok`**, leaving failures (and timeouts) on screen, with the script also blocking (`read`) on failure so the window survives regardless of Terminal prefs. All output is tee'd to a per-day `addons-output/break-summary-YYYY-MM-DD.log` (a closed window is never a lost post-mortem). The banner falls back to the **newest-mtime session folder** when the literal date isn't a substring of the folder name (multi-day sessions are named `2026-06-29..30 Topic`, so on day 2 `grep 2026-06-30` misses; claude's own Step 0 resolves it regardless). Trigger headlessly with `GET /test/break-summary`.
- **📝 Wrap-up offer at 16:45 / 17:15, weekdays only (`SummaryReminder` + `SummaryReminderPolicy`)** — on **Mon–Fri** (a Saturday afternoon has no session to write up, so the pill would only interrupt; public holidays are deliberately *not* modelled — that needs a calendar per country Victor is in, and an unwanted pill costs a glance) at both times a bottom-left hoverable pill asks **`Start summarization?`**; a deliberate hover (the standard moving 2 s dwell, `HoverMotionGate`) opens a **new Terminal running an *interactive* `claude`** in `~/workspace`, primed with `/victor-skills:training-summarizer`, and floats the pill up (`dismissRisingFade`); letting the window lapse drops it (`dismissSinking`). **Interactive, not `-p`** — unlike the break-delta (`BreakSummaryLauncher`) the wrap-up is a conversation Victor steers, so nothing waits on the window, there is no sentinel and no auto-close. It runs on the **subscription** (`env -u ANTHROPIC_API_KEY`) for the same reason every other launcher here does. **Two slots, not one:** 16:45 is usually mid-sentence in the last section, so missing it is expected and 17:15 catches the same day once the room is done — which is why answering the first must not suppress the second (each slot is keyed separately). The hover window is **~10 s of *un-hovered* time** (the countdown pauses while the cursor is on the pill): the offer is glanceable — either Victor is at the Mac and reaches for it, or he isn't and the 17:15 slot asks again — and a pill that lingered would park itself over the projected screen. **The clock is polled every 20 s rather than scheduled**, because a Mac asleep or shut at 16:45 never fires a scheduled timer at all — a poll just notices on the next tick that the slot is due; and a slot stays due for `graceMinutes` = 10 min so a slot that came due while the app was down (rebuild, wedged relaunch) still fires a few minutes late instead of being lost. Fired slot keys are **persisted** (`summary.reminder.fired.slots`, pruned to today) so the app's several restarts a day can't re-ask an answered question. Schedule decisions are pure + unit-tested in `SummaryReminderPolicy`. Test hook: `GET /test/summary-reminder`.
