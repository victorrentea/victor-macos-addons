# Break Timer & Break-Triggered Prompts

The ☕️ countdown overlay, the coffee hold-charge gesture, and the Group Photo prompt a break raises at both of its ends. The break-triggered summary run lives in `summaries.md`.

- **☕️ Break (countdown watch)** — a **☕️ Break parent row** whose submenu holds the fixed durations (1/5/10/12/15/30/45 min, 1 hour) opens a draggable, resizable digital countdown overlay (`BreakTimerOverlay`): a big **red seven-segment** `MM:SS`. The segment shapes are **reverse-engineered polygons** traced from a reference LED watch (`Self.segPolys`, canonical cell 80×137; irregular hexagons — outer edge full width, inner edge beveled 45°), laid out in two pairs with the **digit↔colon gap halved**. **Unlit segments are not drawn** (absent, not dimmed); each lit segment gets a **2px black outline** so it reads on any backdrop. Finish time shown on a **single row** (one flag + one `HH:mm`, no AM/PM, in a **slightly larger** font), in the **picked country's** timezone. The selection is **day-scoped and auto-detected**: on the **first Break start of the day** `BreakCountry.autoSelectForToday()` auto-picks "where I am now" — the country matching the Mac's **live system timezone** (`TimeZone.current`, which macOS auto-updates by location as Victor travels; pure map `country(forTimeZoneIdentifier:)`, falling back to 🇷🇴 Romania when the zone isn't listed) — and **persists it for the rest of the day** (`BreakTimer.country.tz` + `BreakTimer.country.day`), so later starts today reuse the same value even if the zone shifts, and every new morning it re-detects. A **manual dropdown pick** made during the day is stored the same way and wins over the auto-pick. (`loadSelected()` is now the read-only, no-side-effect view of today's stored pick, defaulting to Romania.) **Clicking the flag/time row** opens a **searchable country dropdown** (`CountryPicker`): a borderless key panel whose search field filters a broad global list (`BreakCountry.all`) by name *contains* (typing "arg" → just Argentina), ↑/↓ move, ⏎/click pick, Esc/click-away close; each row shows flag + name + that country's current local time. With **no query, 🇷🇴 Romania is pinned at the top** (above a thin `NSBox` **divider**), then the rest alphabetically — a one-click "back home"; while filtering, only the contains-matches show (no pin/divider). **The durations live in a submenu, and the country is pickable from the menu bar too.** The seven duration rows used to sit flat in the main menu, each repeating the `☕️ Break: ` prefix — a list of one feature's arguments occupying the top level. They are now one `☕️ Break` parent; inside it the prefix is dropped (the parent already said "Break") and the emoji carries the only distinction left: **☕️ up to 15 min, 🍽️ from 30 min up** (30/45/1 hour), where the room actually goes to eat rather than to refill a cup. **45 minutes** was added there — the length of a real lunch that isn't a full hour. Directly under it, a **🌍 country row** (`MenuBarManager.refreshCountryItems`) offers `BreakCountry.trainingCountries` — the shortlist of countries Victor actually delivers in, Romania pinned first and the rest alphabetical, each row flag + name with a ✓ on today's pick — and writes the very same day-scoped selection the overlay's dropdown does (`BreakTimerController.selectCountry`, now internal for that reason; `refresh()` is a no-op with no window up, so a pre-break pick simply lands in `UserDefaults` and the next `start()` reads it). It exists because the overlay's flag/time row **only exists while a countdown is showing**: before the first break of a trip there was nowhere to say "I'm in Amsterdam today". The parent's own title is the readout — `🇳🇱 Netherlands (now: 15:32)`, the flag standing in for the row's own icon — rebuilt on every `menuNeedsUpdate`, since that `HH:mm` is exactly the number being read off the projector when the break ends, and a title written once at build time would show the hour the app was launched. The picker is a `Row` enum (`.country`/`.separator`); separators are never selectable and are skipped by all keyboard/selection helpers. The app is an accessory, so the picker calls `NSApp.activate` to receive keystrokes. Small controls left→right (+1/+3/+5, ⏸ pause/resume, ✕ close). **⏸ freezes the duration, not the wall clock:** the digits stand still while the finish time keeps sliding a minute further into the future every minute the break is held (the 1 s timer therefore keeps running while paused and only skips the decrement — `refresh()` always computes `now + remaining`). It used to be anchored to the moment ⏸ was pressed, which is the one reading the room acts on: everyone reads that `HH:mm` off the projector, walks away, and comes back to a break that hasn't started counting again. Opens top-right at **20% of the main-screen width** (aspect 1.85), draggable (open/closed-hand cursor) and corner-resizable (OS diagonal resize cursors) with locked aspect ratio. The **backdrop is a separate opaque-black layer** (`bgView`): **opaque black by default at all times**, fading **fully transparent only while the cursor hovers over the timer panel** (`panel.frame.contains(mouseLocation)`, sampled every 0.15 s) so you can peek at what's underneath, then back to black when the cursor leaves — one GPU alpha fade per transition (no flicker). **Hovering peeks; it never takes focus.** `mouseEntered` used to call `window?.makeKey()` so AppKit would honour the view's cursor *rects* — but a `.nonactivatingPanel` becoming key, while it doesn't activate the app, still resigns key status from whatever window had it, so simply sweeping the cursor across the corner where the timer parks pulled the caret out of a text field in another app with no click involved. The mouse crossing a widget is not a decision to leave what you were doing. The `makeKey` is gone and nothing was lost: `updateHover` already sets every cursor imperatively (`NSCursor.set()`, which needs no key status) and the tracking area is `.activeAlways`, so enter/exit/moved keep arriving with the app inactive. (This replaced the older idle-driven model that was transparent while active and went black after idle.) **Fullscreen "break screen" on idle + transcript silence:** after **120 s of total inactivity** (mouse + keyboard, `systemIdleSeconds`) **during which nothing was transcribed** — today's `…-transcription.txt` must also be 120 s stale (`AppDelegate.transcriptSilenceSeconds`, probed at most 1×/s and injected via `BreakTimerController.transcriptSilentSeconds`; the AND lives in the pure `BreakTimerModel.shouldShowBreakScreen`) — the timer becomes a hands-off pause screen. The transcript gate exists because Victor keeps **talking** to the room while not touching the Mac: as long as Whisper is appending lines, the projector must not go black; new lines landing also **exit** fullscreen, exactly like a keystroke. With transcription off the file never grows (`.infinity` silence), so idleness alone decides as before — the panel **fills 100% of the retina** (`BreakTimerModel.fullscreenFrame`, a non-aspect black desktop-like fill, corner radius dropped to 0; the retina specifically, even if the panel was dragged to another display), **every other connected display is blacked out** (an opaque, click-through `NSPanel` per non-retina screen, faded in), and an **`IOPMAssertionTypePreventUserIdleDisplaySleep` wake lock** keeps the Mac from sleeping so the countdown stays visible through the whole break. The backdrop stays **always black** while fullscreen (hover no longer peeks). **Any input** — a mouse move or keystroke, on any screen — restores everything in one step: the panel shrinks back to its saved frame + corners, the blackout covers are removed, and the wake lock is released. Teardown also runs on close/expiry. **Black screen after the break ends (`ScreenBlackout`):** a close of a showing timer — the ✕ button, the countdown expiring after the gong, or a programmatic/`/test/break/close` stop — leaves **every connected display covered by an opaque black panel until the next user input**. The break being over doesn't mean Victor is back in the room, and the projector must keep showing nothing rather than snapping to his desktop. **One exception — an expiry that finds him already at the Mac:** if there was any input in the **10 s before the countdown hit zero** (`ScreenBlackout.Policy.shouldBlackoutOnExpiry`, pure + unit-tested), the whole blackout is skipped — there is no empty room to protect, and the covers would only flash black over what he is working on until his next mouse move took them down. The verdict is sampled **at zero**, not at the close ~2 gongs later, and remembered in `BreakTimerController.skipBlackoutOnClose` (cleared by every start / +Nm / close, so it can never leak into a later ✕). A ✕ close still blacks out unconditionally: clicking it *is* input, so gating that on recent activity would disable the feature. The covers come down on the first mouse move / keystroke that happens **after** they appeared (pure `ScreenBlackout.Policy.shouldDismiss`, polled 10×/s against `secondsSinceLastInput()`), so the very click that hit ✕ never dismisses its own blackout — but a hand still on the mouse clears it a moment later, by design. Covers are click-through (a stuck cover can never trap the Mac), fade in over 0.35 s — **instantly (no fade) when the timer was the fullscreen break screen**, since the screen is already black and a fade would flash the desktop between the two blacks — and fade out over 0.3 s. Unlike the fullscreen break screen it holds **no wake lock**: with no countdown left to read, normal display sleep is welcome, and whatever input wakes the display also dismisses the covers. A projector plugged/unplugged while black rebuilds the cover set. Starting/resuming a break dismisses it. Re-clicking a duration resets the time in place. On expiry the gong plays **once** while the digits **blink for the gong's duration**, then the window **closes instantly**. Pure formatting/finish-time math lives in a unit-tested `BreakTimerModel`; an `epoch` counter cancels in-flight expiry on +Nm / re-click. The SVG generator + diff harness used to reverse-engineer the segment polygons lives in the session scratchpad (`build_svg.py`).
- **☕ Coffee hold-charge → start / shorten a break (`EmojiAnimator.tickCoffeeCharge` + `AppDelegate.installCoffeeBreakHoverMonitor`)** — participants fire ☕ emoji reactions that rise from the bottom-left (`spawnEmoji`). Resting the cursor on one now **catches** it: a 0.1 s poll (not `.mouseMoved`, so a still cursor works too) freezes the coffee where it visually is, takes it out of the auto-rising pool, and **grows it steadily for 3 s** — the growth *is* the hold's progress bar. Completing the hold **shatters** it: the ☕ layer is removed in the same frame and **its own rendered pixels take its place** (`EmojiAnimator.pixelDissolve`) — the glyph is diced once into a 12×12 grid of square tiles (cached, cut with the same top-anchored layout `CATextLayer` draws it with, so each fragment starts on exactly the pixels it replaces) and each tile drifts outward from the centre along its own direction, turning, shrinking and fading, while the whole cloud blooms 1.25×, so the cup visibly **enlarges as it comes apart**. Spin and shrink are baked into **one keyframed `transform`**, not two animations on `transform.rotation` + `transform.scale` — those fight over the same property and the fragments jitter instead of tumbling. It is deliberately **gentle**: the first version threw fragments 1.5 cup-widths at ±2.6 rad under a 0.95-alpha white flash and Victor's verdict was *"se sparge prea violent"* — a **dissolve**, not a detonation, is the effect being asked for, so the travel is 0.18–0.55×, the turn ±0.7 rad over 0.8–1.25 s, the fade starts a quarter of the way in and the flash is a soft 0.45 glow. (This replaced a 💥 emoji pasted over the cup, which read as a *second emoji arriving* rather than as the cup breaking.) The 3-second deliberate hold — not a graze — is the trigger, so it runs even mid-break without accidental firing:
    - **No break showing → the first explosion starts the 10-min half-size "UNTIL BREAK" timer, which GROWS OUT OF THE BLAST**: `BreakTimerController.start(…, zoomFrom:)` puts the fresh window up as a tenth-size copy centred on the explosion and flies it to its corner over **2 s** (`zoomInSeconds`). Slow on purpose — that travel is the only announcement the countdown gets, and it is what connects "coffees are popping" to "there is now a clock". The backdrop's **corner radius is animated along with it**, since the radius computed for the full size rounds the tiny window into a pill for the first second. Only a *fresh* window flies in; a re-click must never send a running countdown across the screen.
    - **A break already running → each explosion sends a big red `−1` floating to the clock** (`EmojiAnimator.flyMinuteToken`), shrinking to **half** its size as it closes in, and the minute comes off **when it lands** — `addSeconds(-60)` plus `reactToMinuteRemoved()`, a white flash of the backdrop and a 4 % nudge of the window. **Deferring the deduction to the arrival is the whole point**: the number you watch arriving *is* the deduction, so a cluster of coffees popping reads as several minutes converging on the watch instead of digits quietly dropping by 3 while something happened elsewhere. The target (`tokenTargetGlobal`) is **re-sampled every frame**, not captured once, so a token launched while the window is still flying in — or while it is being dragged — still ends up where the watch actually is; if the timer is closed mid-flight the token fades out and **nothing is subtracted**. The jolt keeps a pre-jolt `joltBase` so overlapping tokens can't grow the window for good, and it stands down while the fly-in owns the frame (two frame animations fighting) or while the panel is the fullscreen break screen (that would be a strobe, not feedback).

    The cursor slipping off before 3 s **cancels** that coffee (it fades away). A caught coffee's original rise/fade completion block is guarded by `chargingCoffee === layer` so it isn't yanked off screen mid-charge. **Every coffee under the cursor charges at once** — parking on a cluster inflates the whole cluster, each on its own 3 s clock, and they pop as they ripen; only the ones that actually **explode** count (`tickCoffeeCharge` returns the per-tick explosion **POSITIONS** — global coords, not a count and certainly not a Bool: both payoffs start *at the coffee*, so the caller needs to know where each one popped). Leaving one coffee's box cancels just that one; the siblings keep charging. **The "UNTIL BREAK" timer is not a break** — closing it (✕ or reaching zero) does **not** fire `onEnded`, so it never resets the menu's **⏱️ Resumed Xm ago** clock or re-arms the break reminder: that clock measures time since the last *actual* pause, and an UNTIL-BREAK hitting zero is the moment a break is *due*, not one that just finished. Only titles other than `BreakTimerModel.untilBreakTitle` count (pure `BreakTimerModel.endsABreak`, unit-tested). Headless tests: `GET /test/coffee` spawns 3 coffees to hover; `GET /test/coffee/pop` skips the hold and pops one fully-charged coffee mid-screen, running the whole payoff.

- **📸 Group Photo (break-triggered, at BOTH ends of the break)** — instead of a fixed clock time, the Group Photo reminder fires at the **start of a qualifying break** and **again when that break ends**. When a break starts (`MenuBarManager.onBreak` → `AppDelegate.startBreak`), the pure, unit-tested `GroupPhotoBreakPolicy.shouldPrompt(breakMinutes:at:)` decides: a **lunch** break (≥ 60 min, any time of day) **or** an **afternoon** break (≥ 10 min starting at **13:00** local or later) qualifies; morning coffee breaks are ignored. The prompt only fires when the **training-assistant daemon is connected** (`daemonConnected` — the local WS server has ≥1 client, tracked in `onClientCountChanged`), i.e. there's an audience to photograph. `promptGroupPhoto` shows it through the app's **standard bottom-left `StatusBanner`** — the same overlay as "started" / "paused on battery" / etc. — with text `📸 Group Photo`, the start chime, and a 12 s visible duration. It's **presence-gated** (`showOnPresence`), so if Victor stepped away it fades in the moment the laptop sees input again — **any** input, keyboard included, not just a moved cursor. Being the app's own always-on-top panel it shows **even while PowerPoint is presenting fullscreen / mirroring to a projector** — which is exactly when macOS would suppress a native notification silently into Notification Center (the reason we don't use one here; the "Allow Time Sensitive Notifications" toggle never appears for this locally-signed, un-entitled app anyway).
  - **Why twice.** The prompt at the start lands in a room already standing up to leave, and an hour later nobody remembers the photo was owed. The end of the break is when everyone walks back in, which is when the shot actually happens — and since the banner waits for presence, a lunch break that expires while Victor is still out surfaces on his first touch of the laptop rather than fading into an empty room.
  - **The latch.** A qualifying start stores *when* the break began (`GroupPhoto.breakStartedAt` in `UserDefaults`); `breakTimer.onEnded` → `promptGroupPhotoAtBreakEndIfDue` reads it once and clears it, whether or not it fired. It is **persisted, not in memory**, because the hour Victor is away is exactly when a redeploy happens, and a restart that resumes the countdown would otherwise drop the prompt he'd notice missing. Two guards in `GroupPhotoBreakPolicy.shouldPromptAtEnd`: a break closed **under 5 min** after it started was a misclick, not a break (`endPromptMinElapsed`), and a latch **older than 4 h** is stale (`endPromptMaxAge`) — the app can quit mid-break and leave one behind, and a photo prompt at the end of tomorrow's coffee break owed by yesterday's lunch would be inexplicable. A non-qualifying break start clears the latch, so a short coffee break can never cash in the lunch break's photo.
  - Test hooks: `GET /test/group-photo` shows the banner immediately, bypassing the break + connection gates; `GET /test/group-photo/break-end` runs the *end*-of-break half through the real `promptGroupPhotoAtBreakEndIfDue` with the latch pre-armed, so that half doesn't cost an hour of lunch to see. `GET /test/break/<minutes>` now goes through the same `startBreak` the menu does, gates included, instead of a thinner copy.
