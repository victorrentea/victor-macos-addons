# Keyboard / Emoji Cheat-Sheet Overlays (⌥, ⌥⇧, ⌘⌃)

- **⌨️ Hold-to-see cheat-sheets (`KeymapOverlay`)** — holding a modifier long enough to be *asking* rather than *typing* draws a keyboard on the secondary screen. Two sheets, one renderer, one hold delay (`KeymapHoldCoordinator.delay`: 0.3 s multi-monitor, 1.0 s single, since on one screen the sheet covers what you're doing): **⌥ / ⌥⇧** show the emoji/character each key emits, parsed live out of the active `.keylayout`; **⌘⌃** shows what this app's own ⌘⌃ shortcuts *do*, one word per key (`terminal`, `claude` on **both C and Q** — Q is the permissions-bypassed `cx` —, `notes`, `wispr🎙️`, `tile`, `SRL`, `zoom`, `email`, `catalog`, `todo`, `relay` on D with a 🎯 accent). Three keys answer with a **picture instead of a word**, because a mark is recognised faster than the name of the thing: **L = 📅** (calendar), **G = the Gmail logo** and **N = the Google Docs logo** (the "notes" doc itself — the mark *is* the destination, where S's `notes` is the act of sending something there). The two emoji stay in `CommandControlShortcuts.labels` and are detected by the pure `KeymapOverlayRenderer.isPictogram` — a label that is *nothing but* emoji is drawn big and centred in the whole payload area instead of being shrunk to word size at the bottom (`wispr🎙️` is a word that merely *contains* one, so it must not qualify). The Gmail and Docs marks are bundled PNGs (`Resources/gmail-logo.png`, `Resources/gdocs-logo.png`, listed in `CommandControlShortcuts.artworkNames`, loaded through `artworkImages()`) drawn **straight onto the key with its own transparency intact — no white plate behind it**: every key on this sheet is one flat black, so a white card under a single one is the loudest thing on the whole keyboard. The mark survives the dark background because the M *is* the coloured part; the envelope body Gmail normally paints white simply reads as key. A key carrying artwork counts as **bound** even though its `labels` entry is absent, so `boundKeyCodes` (labels ∪ artwork) — not `labels.keys` — is what the sync test asserts. Four keys also carry a small **corner accent** (`CommandControlShortcuts.accents`) in the top-right, opposite the base letter: **E = @**, **Z = 🔗**, **S = 🚀**, **R = 📋**, **K = 📕** and **M = ✉️**. Their words ("email", "zoom", "notes", "SRL", "catalog", "todo") are nouns — the *thing*, not what happens to it — so the mark supplies the missing verb a beat faster: 🚀 says the selection is launched into the notes, 📋 that the SRL details are pasted rather than opened, 📕 which book "catalog" means; it is drawn at 28pt against the letter's 42 precisely so it reads as a hint on the key and not as a second key label. A test asserts every accented key is one that's actually bound — an accent on a dimmed key would decorate nothing. Which sheet a combination asks for is the pure, unit-tested `KeymapHoldCoordinator.sheet` — deliberately exact, so the mixed combos that are themselves shortcuts (⌘⌃⌥D dark mode, ⌃⌥V notes) show nothing rather than guess. The word sheet renders through the same `KeymapOverlayRenderer` in `.word` style: the letter shrinks to the top-left corner to make room, the word wraps across the bottom at a size chosen by its length (`wordFontSize` — word-wrap cannot break a single word, so an oversized font spills over the key border instead of wrapping), and **keys with nothing bound are dimmed to 22% while bound ones keep the full-brightness border**, so the eye lands only on what's live. The ⌘⌃ image is built **in the controller's `init`, not from the layout file**: those are app shortcuts, not characters, so a failure to locate the `.keylayout` must not take the shortcut sheet down with it (which also means `images` is never empty — the layout retry now asks `images[.option] == nil`). Pressing any key under either modifier drops the overlay (`keyDownWhileModifierHeld`): the hold turned out to be a real shortcut. `CommandControlShortcuts.labels` is the map and **must stay in sync with the ⌘⌃ branches in `EventTapManager`**; a test asserts the exact key-code set. Two deliberate exceptions to that rule, both documented in the map: **⌘⌃W is on the sheet but NOT bound here** — it is Wispr Flow's "paste transcript", and the sheet answers "what does this combination do on this Mac", so an empty key would be the wrong answer (the tap's ⌃W → 🔥 Whip branch requires `!hasCmd`, so ⌘⌃W passes straight through); (**⌘⌃V used to be the second exception**, bound but deliberately blank, because while it meant the emotional paste it would have put a second "paste" on a board where ⌘⌃W already says it — and two keys reading the same word makes the reader pick wrong at speed. It now reads `spus` with a 🎙️ accent: what the key does is no longer a paste at all, and "said" is the one word that separates text coming out of your mouth from text coming off a clipboard.) The **Emoji Overlay** menu item toggles both sheets.
